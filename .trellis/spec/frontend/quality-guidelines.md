# Reader Quality Guidelines

The offline reader is standalone HTML/CSS/JavaScript generated by Python.
The optional database editor uses Vue 3 with a Node SQLite service. Shared
contracts live in
[Export Contract](../backend/export-contract.md).

## Quality Check

- Use English/ASCII directory/file names. Default HTML text is Simplified
  Chinese; every page declares `lang="zh-CN"`.
- Preserve original messages, names, emoji tokens and unknown content. Escape
  user text before HTML insertion, including attribute values.
- Navigation, search, playback prompts and explanatory text are Chinese.
- Every local link resolves within the export. A remote source URL may appear
  as an explicit fallback. Local playback needs no server, login or remote
  script/style dependencies.
- Preserve original audio attachments and manifest voice messages. Compare
  counters with matching populations; total audio elements may exceed voices.
- Changing page size removes only recognized obsolete generated pages and
  preserves unrelated user files.
- Run `python -m unittest discover -s tests -v`. For real exports run
  `duoshan-export validate OUTPUT --decode-media` when decoders are installed.

Tests assert Chinese UI and ASCII paths separately, keep original content
verbatim, and check structure/CSS classes/links independently of label text.
Do not make validation depend on translated labels or translate original
messages to satisfy language tests.

## Vue database editor

- Use Vue text interpolation for chat text and raw JSON; never `v-html`.
- Keep IDs as strings through requests, state and component keys. Raw JSON
  is original TEXT from the server, not a parsed JavaScript object.
- Keep API, media and built asset URLs relative to the document; Vite `base`
  is `./`. A proxy prefix must end in `/` and be stripped upstream.
- Render only contained local attachment URLs. Show explicit unavailable
  states rather than loading expired or remote resource URLs automatically.
- Preserve original bubble/inline emoji metadata and place message text above
  animated corner layers. Keep original audio attachments as well as voices.
- Surface edit/hidden badges, revision conflicts and restoration clearly.
- Translate API failures into Chinese display messages while retaining machine
  error codes. Ignore stale account/search responses after a newer request.
- Run `npm run build` and `npm test`. Do not describe compilation or HTTP
  probes as visual browser verification.

## Bulk actions and date browsing

- Paginate conversations and messages independently. Current-page select-all
  may retain selections across pages of the same query; clear selection when
  account, conversation, search, selected date or hidden scope changes.
- Store selected message revisions and conversation counts. Send batches of
  at most 500 with `confirm_delete:true`; never replace revision conflicts
  with guessed values or silently split an atomic request.
- Show Chinese permanent-delete confirmation with selected item count,
  `reader.sqlite` boundary and irreversible nature. Preserve selection on
  failure; offer cancellation/retry and disable double submission.
- Keep restore on `POST api/message/restore`. A permanent delete must never
  reuse the restore action. Refresh account/conversation/message/calendar
  counts after deletion and clamp an emptied page to the last valid page.
- Render calendar month/day/counts from `api/calendar`, display export
  timezone, filter messages with `date=YYYY-MM-DD`, and offer clear-date.
  Do not bucket timestamps using the browser's local timezone.
- Edits to effective text/notes under search and hide/restore can change
  result membership. Refetch both page and calendar when this happens.
- Capture account/query scope before awaits. Ignore stale annotation/error
  replies and cancel pending destructive confirmations/retries after scope
  switches. An old account's request cannot modify a new account's state.
- Verify through deferred-request client tests, independent SQL/HTTP tests,
  production build and Chinese/relative-asset checks. Keep private real data
  out of fixtures and never test deletion on the live reader database.
